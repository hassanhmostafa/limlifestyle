# LIM Events: Consultation Modes and Automatic Recommendations

## Scope

This document defines the two supported consultation modes for **new** LIM Events registrations:

| Mode | Required flow | Recommendation author | Participant-facing attribution |
|---|---|---|---|
| `physician` | Body analysis → optional nursing → physician approval | Assigned event physician | **توصيات الطبيب** with the physician name |
| `automatic` | Body analysis → **required completed nursing** → automatic recommendation generation | Allowlisted lifestyle guidance selected by the server | **توصيات نمط الحياة للفعالية**; no physician name and no AI label |

Existing visits retain their snapshot configuration. Changes to mode, questionnaire selection, nursing enablement, or nursing tests affect only newly created visits.

## Safety boundary

- Automatic mode can be configured only when nursing is enabled and at least one nursing test is selected.
- The automatic path does not create diagnoses, medication advice, calorie targets, exercise clearance, or recommendations based on body age/BIA alone.
- Free-text nurse notes, names, phone numbers, session codes, and identifiers are excluded from the recommendation input.
- The model selects **only IDs** from a server-owned allowlist. The server renders the Arabic text; unrestricted model prose is never stored or shown.
- A deterministic urgent rule applies when `SBP > 180` or `DBP > 120` from the linked X18 reading or completed nursing blood-pressure fields. It asks for a repeat measurement and urgent clinician review; listed emergency symptoms require immediate emergency care. It suppresses generic exercise advice.
- Each automatic visit has a maximum of two recommendation-generation attempts. A failure remains visible to nursing staff for a controlled retry; it is never represented as a successful report.

## Evidence records

The system stores only the following internal source IDs in staff/admin metadata; it does not claim that patient-facing wording is a direct quotation.

| Source ID | Bounded use |
|---|---|
| `RIPPE_ACTIVITY` | Gradual activity, reduced sedentary time, 150 minutes/week moderate activity and strength work on at least two days when appropriate |
| `RIPPE_NUTRITION` | Vegetables, fruit, fibre-rich whole grains, reduced sugary drinks, Mediterranean-style pattern respecting preferences/allergies |
| `RIPPE_TOBACCO` | Tobacco cessation support only if the participant reported current use; no medication advice |
| `RIPPE_BEHAVIOR` | Collaborative small, specific, measurable, realistic goals and self-monitoring; non-diagnostic stress support |
| `RIPPE_CONNECTION` | Supportive contact and connection without quantified claims |
| `CDC_SLEEP_7H` | Adults generally need at least seven hours of sleep daily; regular sleep routine advice |
| `AHA_BP_180_120` | Deterministic urgent blood-pressure recheck/review and symptom escalation rule |

Reference links used for the source records: [RIPPE lifestyle summary](https://www.rippehealth.com/healthy-lifestyle), [CDC adult sleep guidance](https://www.cdc.gov/sleep/data-research/facts-stats/adults-sleep-facts-and-stats.html), [WHO physical activity guidance](https://www.who.int/initiatives/behealthy/physical-activity), and [AHA blood-pressure categories](https://www.heart.org/en/health-topics/high-blood-pressure/understanding-blood-pressure-readings). The shipped wording is implementation-specific Arabic education, not a clinical protocol or direct quotation.

## Data flow

1. Super admin configures the mode and nursing tests in `/events/care-admin`.
2. Registration snapshots the event questionnaire selection in `event_participant_sessions` and nursing/mode settings in `event_care`.
3. The physical X18 upload continues through the existing shared `/api/kiosk/data` endpoint and links a result to the latest Event visit.
4. Nursing completes its required configured measurements.
5. For automatic mode, the server claims the visit atomically, builds a minimised non-identifying input, applies the urgent safety rule or asks the structured model to rank allowed suggestion IDs, then persists rendered advice plus internal source metadata.
6. The participant can view the report only after `approvedAt` is set. Staff/admin may view internal source IDs and generation state; participants do not receive model or source metadata.

## Storage additions

`event_settings.consultationMode` is the default for future registrations.

`event_care` stores the snapshot and audit state:

- `consultationMode`
- `recommendationMeta` (allowlisted IDs/source IDs and prompt version)
- `autoGenerationState`, `autoGenerationAttempts`, `autoGenerationError`
- `autoGeneratedAt`, `autoModel`

## Operational cleanup plan

`scripts/dry-run-delete-scoped-events-test-results.mjs` is safe by default. It reports counts only and does not print personal information.

Its deletion scope is deliberately narrow:

1. Results with an explicit historical Events test marker (`EVENTS_TEST`, `EVENT-TEST-*`, or the original Events test-upload note).
2. Simulator results currently linked to an Events visit.

It preserves physical X18 readings, ambiguous/shared readings, user accounts, Event visits, care rows, staff, tracks, profile/settings, and research records. The script requires both `--apply` and the exact environment confirmation value `DELETE_PROVEN_EVENT_TEST_RESULTS`; it clears only the affected Event-result links in the same transaction so sessions cannot point to a deleted result.
